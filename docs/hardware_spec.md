# 🧭 ハードウェア設計・実装構成

本章では、**S310** 機体搭載用の計測システムにおけるハードウェア構成・実装方針をまとめる。  
計測システムは、**配線簡略化と信頼性向上**を最優先目標として設計されており、主要デバイスには**I²C 通信**を採用し、機器接続には**XH コネクタ**を統一的に使用することで、**振動耐性・防水性と高い整備性・交換性**を確保した。

## 2. 設計方針と通信構成

- 通信バス設計  
  主要センサーは I²C 通信を採用し、配線を 4 本（VCC, GND, SDA, SCL）に統一。  
  これにより、配線量を削減し、機体内部のスペース効率および整備性を向上させた。  
  一部アナログ出力（舵角計）のみ、直接 ADC 入力として基板に接続。

- 電源系統  
  すべてのセンサーは 3.3V 系統で駆動。  
  ※ ESP32、表示機器 LCD1602 は 5V 電源使用

- 接続インタフェース  
  センサーと基板の接続には XH コネクタを使用。  
  極性防止と確実な保持を両立し、飛行中の振動環境下や雨天環境下でも安定動作を確保した。

## 4. メイン基板の設計
### 4.1 要件
メイン基板の要件は、以下の通りであった。
 - バッテリーには18650電池を直列で2個使用
 - マイコンにはESP32 32Eを使用
 - センサとして高度計（超音波センサ）、姿勢角計（9軸センサ）、回転数計（フォトインタラプタ）、トリムボタン×3（タクトスイッチ）を搭載
 　※基板発注後、高度計のみの使用に変更
 - 表示器としてLCDを搭載
 - 設置場所はコックピット内

### 4.2 設計思想
以下の3つを特に意識した。
 - コンパクトさ
 <img src="./images/main-3d.jpg" alt="メイン基板 3Dモデル" width="600">
 ESP32の下のスペースに、可変抵抗を配置。バッテリー設置スペースも基板上に用意。メイン基板全体として使うスペースを削減し、コックピットの何処にでも設置可能に。

 - 取り付けやすさ
 <img src="./images/main-mount.jpg" alt="メイン基板 マウント" width="600">
 マウント作成に、形状を自由に決められる3Dプリンタを初導入。上記写真下部のパーツを事前に桁に固定。基板が格納された上部のパーツをスライドして差し込むだけで基板の固定が可能に。従来の結束バンドと比べ、接合時間を大幅減。また、トラブル時の対応も簡単に。

 - デザイン
 マウント上部にコンセプトネームのデザイン。コネクタを均等に配置。電源用トグルスイッチも簡単に触れる用に工夫。あかつき色LEDで電源ONを明示。

### 4.3 作成手順
以下の手順で作成した。
 - 回路設計・動作確認
 　<img src="./images/main-breadboard.jpg" alt="メイン基板 ブレッドボード" width="600">
   まず、ブレッドボード上で要件を満たす回路を組み、適当なプログラムで動作チェックを行う。理論上は動く回路であっても、電流とか電圧の関係で動かない可能性があるため、pcbソフトで設計する前に、必ず行うべき。

 - 回路図作成
   <img src="./images/main-diagram.jpg" alt="メイン基板 回路図" width="600">
   PCBソフト（Fusion PCB（旧 Eagle））上で、ブレッドーボードで動作確認した回路と、同じ回路を作成する。

 - 電子部品の配置決め
   <img src="./images/main-2d.jpg" alt="メイン基板 2D" width="600">
   回路図ドキュメントからPCBドキュメントに切り替え、部品の配置を決める。出来るだけコンパクトになるよう意識する。電源周りなど、電流が多く流れるところは太くする。さらに、ベタグラウンドを行いノイズを削減する。最後にオートルータで回路を生成する。

 - 出来上がり確認、基板発注
 　<img src="./images/main-3d.jpg" alt="メイン基板 3D" width="600">
   3Dに起こし、干渉を確認する。問題なければ会社に発注する。310ではJLCPCBを利用した。

 - マウント作成
 　<img src="./images/main-mount.jpg" alt="メイン基板 3D" width="600">
 　基板の3Dデータをベースに、基板マウントをFusionで設計する。アセンブリ出来るかや、強度なども考慮する。

### 4.4 課題・反省点
後々こうすれば良かったと思うことや、実際にTFなどで運用して気づいたメイン基板に関する課題点をあげる。
 - 発注後の変更が多かった
 　基板発注後に、仕様変更などで使わなくなった計器が多数あり、無駄なコネクタが増えてしまった。最初から分かっていれば、基板サイズを更にコンパクトにできた。

 - 電流・電圧に関する計算を行っていなかった
   ブレッドボード上で動作したら「ok」としており、電流・電圧に基づく抵抗やコンデンサの選定をしていなかった。これが原因で、LCD点灯時に不具合が発生したと思われる。また、18650電池2本の7.4vから降圧する際のロス大きかった。　

 - 重量を意識していなかった
   他班が数gの軽量化のために努力をしているにも関わらず、基板やマウントについて、余分な箇所が多かった。例えば、18650電池boxを置くための基板上スペースについて、わざわざ下に基板は必要なかった。

## 5. TB基板の設計
### 5.1 要件
TB基板の要件は以下の通りであった。
 - バッテリーには18650電池を直列で2個使用
 - マイコンにはESP32 32Eを使用
 - センサとして、機速計（差圧センサ）、舵角計×2（ポテンショメータ）、0点ボタン×2（タクトスイッチ）、姿勢角計を搭載
  （姿勢角計は当初メイン基板に搭載予定だったが、LCD点灯時に値が取れなくなる不具合のため、TBに移動。I2Cのため、発注した基板を変更する必要は無かった）
 - 設置場所はTB付近

### 5.2 設計思想
以下の3つを特に意識した。
 - コンパクトさ
 <img src="./images/tb-mount.jpg" alt="TB基板 マウント" width="600">
 テールビームに取り付けるため、細長くコンパクトな形状にする必要。マウント上部を桁に沿うように円形にし、取り付けも簡単に。すべての部品を寄せ、無駄なスペースができないように。また、コンパクトにしないとマウント印刷用の3Dプリンタの印刷可能域に入らないという問題もある。

 - 抗力減
 マウントの形を翼型にし、抗力減。マウント印刷時、下部のパーツは積層の跡が残りにくいように、フィラメントを一度も止めず螺旋状に印刷するように設定している。これにより抗力を減らしている。

 - 熱対策
 TB付近は太陽光が直接当たり熱くなるので、マイコンの温度上昇を抑制するため、インテイクとアウトテイクを設置。マイコンのCPUを冷やせる構造に。

### 5.4 課題・反省点
後々こうすれば良かったと思うことや、実際にTFなどで運用して気づいたTB基板に関する課題点をあげる。
 - 抗力や風の流れを解析していない
   翼型にしているので、抗力は減っていると思うが、どのくらい効果があるか不明なため、CFD等を使用し解析すれば良かった。

 - 重量を意識していなかった
   メイン基板と同様。他班が数gの軽量化のために努力をしているにも関わらず、基板やマウントについて、余分な箇所が多かった。

 - ピトー管関係
   きちんと校正していない、ペラの後流の影響を受ける可能性がある、という問題があり、信頼性0だったので、来年は風洞を使い校正した上で、キングポストに付けるべき。

 - 防水対策
   TF時、結露でTBが結構濡れるが、その水がマイコンに付着する恐れがあった。実際には、マウントとTBの間に挟んだ緩衝用のスタイロが吸収してくれたようだが、いつマイコンが濡れてエラーを起こしてもおかしくない状態だった。

 - 舵角計
   最も重要だが、不具合が多々あった。後述の「舵角計の設計」を参照。

## 6. 舵角計の設計
### 6.1 要件
 - 310では初めてWLを採用したが、センタリング機構が無いため、舵角をパイロットに伝え、それをパイロットは注視して操縦する必要
 - さらに、リンケージの紐に使用したダイニーマロープは、伸びが多く、操縦桿のニュートラル位置が不定だったため、尾翼側に舵角計を搭載する必要
 - 尾翼付近で取得した舵角のデータをコックピット内のメイン基板に無線で送信し、パロットに提示
 <img src="./images/dakaku.jpg" alt="舵角計" width="600">

### 6.2 設計思想
 - 最優先
 　舵角計が無いと操縦出来ない機体だったため、他のどの計器よりも優先して、設計・製作・テストをした。

 - 取れにくく取り外ししやすく
   飛行中に取れては大問題だが、計器類に不具合が生じた際、交換できないと問題なため、その両立を図った。下記写真のようなスナップフィットを採用し、尾翼の回転軸にポテンションメータを簡単に取り付け出来るようにした。
   <img src="./images/dakaku-snapfit.jpg" alt="舵角計 スナップフィット" width="600">

### 6.3 課題・反省点
後々こうすれば良かったと思うことや、実際にTFなどで運用して気づいた舵角計に関する課題点をあげる。
 - 舵角計のずれ
 　ドリフトにより舵角計が示すニュートラル位置が頻繁にずれた。原因は2つあると考えている。1つ目は、尾翼回転時にロックナットが回転したこと（舵角計はボルト・ナットが回転しないことが前提の機構だった）。これは、ロックナットを2つ使いダブルナットにすることで改善できた。2つ目は、取り外しをしやすくするために導入したスナップフィットがうまくボルトにフィットせず、尾翼の回転が舵角計に伝わらなかった。
  <img src="./images/dakaku-nut.jpg" alt="舵角計 ナット" width="600">

 - 取り付けにくい
   スナップフィットなどを採用し、取り付け性能の向上を目指したが、結局最後は、マスキングテープをグルグル巻きにして固定する必要があったため、接合に時間がかかった。要改善。
   <img src="./images/dakaku-tape.jpg" alt="舵角計 テープ" width="600">

## 7. データ取得と統合

各センサーからのデータは ESP32 を介して周期的に取得される。  
I²C 通信デバイスは同一バス上でアドレス分離され、姿勢・速度・高度・舵角の各データを同周期（約 10Hz）で統合。  
データは Android アプリおよび Firebase に送信され、飛行ログとして蓄積・可視化される。

## 8. センサーキャリブレーション方法

- 高度計  
  測定範囲が 20cm~765cm なので、地面から 20cm の地点に設置し、その値を 0 として測定

- 姿勢角計
  起動時に初期値を 0 として、そこからのずれ角度で計算
  時間がたつとズレが生じ、特にヨーのずれがひどかったため、リセット処理も追加しようとしたが未実装 - ヨー  
   補正式

      ```c++
      // --- 磁気センサキャリブレーション（回転しながら実行） ---
      if (calibrateMag) { /* ... 最大・最小値の更新 ... */ }

      // ハードアイアン補正
      float magOffsetX = (magMaxX + magMinX) / 2.0;
      float magOffsetY = (magMaxY + magMinY) / 2.0;
      float correctedMagX = magRaw.x - magOffsetX;
      float correctedMagY = magRaw.y - magOffsetY;
      ```
      センサーを回転させたときの地磁気の最大値・最小値を記録
      最大値と最小値の中央値をオフセットとして、現在の地磁気生データ（magRaw）から差し引くことで補正

      計算式
      ```c++
      // チルト補正付き磁気方位角の計算
      float xh = magRaw.x * cos(pitchRad) + magRaw.z * sin(pitchRad);
      float yh = magRaw.x * sin(rollRad) * sin(pitchRad) + magRaw.y * cos(rollRad) - magRaw.z * sin(rollRad) * cos(pitchRad);

      float heading = atan2(yh, xh) * 180.0 / PI;

      // --- 地磁気に基づくyawの更新 ---
      yaw = 0.90 * yaw + 0.10 * heading;
      ```
      機体が傾いている（ロールやピッチがある）場合、地磁気の値が歪むため、**ロール（rollRad）とピッチ（pitchRad）を使ってその影響を打ち消す（チルト補正）

      地磁気で計算した新しいheading（方位）と、以前のyaw（ヨー）を**重み付けして平均する（相補フィルターや簡易的なカルマンフィルターの考え方）**ことで、ヨー角をスムーズに更新

      - ロール、ピッチ
      初期値からのずれ角度を計算
      ```c++
      // --- ロール・ピッチ計算 ---
      float accRoll = atan2(accRaw.y, accRaw.z) * 180.0 / PI;
      float accPitch = atan2(-accRaw.x, sqrt(accRaw.y * accRaw.y + accRaw.z * accRaw.z)) * 180.0 / PI;

      roll  = alpha * roll  + (1.0 - alpha) * accRoll;
      pitch = alpha * pitch + (1.0 - alpha) * accPitch;
      ```

      前の角度（roll, pitch）に重みalpha（ジャイロの寄与）をかけ、加速度計の角度に重み(1.0 - alpha)をかけて加算する **相補フィルター（Complementary Filter）** 使用

## 9. まとめ

計測機器群は、軽量・低消費電力・高信頼性を指針として選定した。  
I²C 通信による共通化およびコネクタ統一設計により、再現性の高い配線構成とメンテナンス性を実現している。  
また、センサー配置を流体・構造設計と整合させることで、飛行時のデータ精度を確保した。
